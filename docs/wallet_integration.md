# 拡張ウォレットとWTC

## 利用

Gatewayの`/wallet`を開き、ブラウザーのEthereumウォレットを接続します。利用者が10進chain IDを入力し、ERC-20のコントラクトアドレスを入力します。アドレスを空欄にするとETHです。WTCの配備先アドレスを入力すれば同じ経路を使用できます。資産の小数桁はコントラクトから読み取ります。

送金先と金額を入力して内容を確認し、ネットワーク・資産・送金先・金額・概算手数料を確認後、外部ウォレットで署名します。手数料の最終額は外部ウォレットで確認します。ページには秘密鍵・シード入力を設けず、Gatewayサーバーへ署名鍵や送金要求を送りません。

取引ハッシュの返却は送信済みを意味します。ブロック収録、必要確認数到達、revertを区別し、ERC-20は対象アドレス・金額のTransferイベントも照合します。必要確認数は利用者が指定し、チェーン再編の可能性が完全になくなる保証ではありません。履歴はブラウザーメモリ内のみで、ページ再読込後は外部ウォレットで履歴を確認します。結果不明時に自動再送しません。

日本語・英語・中国語は既存の言語切替を使います。メニュー表示設定でウォレット項目を表示できます。ネットワークや資産の値は利用者が指定し、特定組織・本番配備先を既定値にしません。

## 開発者向け契約

`src/wallet/client.mjs`の`WalletRegistry`は`connect / balance / prepare / send / observe / disconnect`を持つアダプターを登録します。`EthereumWalletAdapter`はEIP-1193経路でETHとERC-20を扱います。他チェーンのアダプターは同じライフサイクルを実装し、chain/account変更時の見積り失効、精度、支払確定根拠を独立に検証してください。

WTC契約・発行・配備は別プロジェクト`wentian-wtc`で管理します。Gatewayは発行権限を受け取らず、法定通貨への換金や価格保証も行いません。現在のウォレット送金は任意送金であり、商取引注文の支払済み状態を自動更新する機能は含みません。

## 検証

`node --import tsx --test src/wallet.test.ts`は金額精度、ネットワーク/口座変更、見積りの再送拒否、確認数とrevertを検証します。ブラウザー検証はローカルEVMの一時口座と一時コントラクトだけを利用します。本番資金・ウォレット・外部チェーンを変更しません。

`python scripts/verify-wallet.py --wtc-project WTCプロジェクトのパス --server GatewayのURL`、または`pwsh -NoProfile -File scripts/verify-wallet.ps1 --wtc-project WTCプロジェクトのパス --server GatewayのURL`で実ブラウザー検証を再現します。NodeとEdgeが必要です。`--output 保存先`を省略すると一時領域へレポート・三言語の画面証拠を出力します。
