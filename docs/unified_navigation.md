# メニュー統一とタスク・成果への統合

2026-10-19

ホーム、タスク、AIグループ、孵化器、独立した機能画面の左メニューを、同じ項目・順序・分類・行先の定義へ統一した。画面ごとに別の「作業台」のメニューへ切り替えない。管理者限定項目の表示制御とAPI側の権限検査は維持する。

「タスク作業台」のヘッダーリンクを削除し、左メニューの「タスク・成果」へ入口をまとめた。上部の製品名はWentianに統一した。モデル・接続の通常入口は共通設定メニューへ集約し、依頼作成はタスク内の切替へ移した。

| タスク内の切替 | 動作 |
|---|---|
| 新しい依頼 | 依頼内容・成果物の条件を入力する |
| 進捗 | タスク一覧、実行・停止・再開、詳細を確認する |
| 成果 | 完了・検証待ちのタスクを絞り込み、既存の詳細・成果検証を利用する |

中央の切替は同じタスク画面内で行い、入力した依頼、モデル選択、既存の操作要素を保持する。「成果」は新しいファイル一覧を別に作る機能ではなく、既存タスクの完了・検証待ちの一覧である。

既存の `/workbench#tasks`、`/workbench#create`、`/workbench#groups` 等は互換経路として維持する。成果タブは `/workbench#results`。URLから直接開く場合、ブラウザーの戻る操作、言語切替でも現在のタブを反映する。既存の接続・会話履歴のURLも残すが、共通メニューに重複入口を追加しない。

同じタブ内の画面移動では、メニュー分類の開閉とスクロール位置をsessionStorageで引き継ぐ。選択中の項目を含む分類は開いて現在位置を示す。保存対象はメニューの表示状態だけで、認証情報は含めない。日本語・中国語・英語の共通翻訳を適用する。

実行処理・タスク保存先・公開範囲を変更するものではない。UI内で同じページにある機能は画面内切替、独立した機能は既存URLへ移動するが、左メニューの分類と項目は同じ定義を使う。

検証は一時DOMと模擬応答で行い、メニュー項目・順序・行先の一致、依頼・進捗・成果の切替、下書き保持、成果の絞り込み、開閉状態の復元、三言語表示、既存の群・孵化器・タスク操作を確認する。本番タスクは作成・実行・削除しない。

関連40試験成功（失敗0、スキップ0）。

型検査成功。稼働サーバーを既存の待受設定で再起動し、ホーム・タスク画面のHTTP 200と更新コードの配信を確認した。独立画面の認証要件は維持する。


## 折りたたみ表示と項目別アイコン（2026-10-29）

幅651px以上の画面では、共通左メニューを幅88pxのコンパクト表示と通常表示へ切り替える。初回はコンパクト表示とし、下部の「展開」「折りたたむ」で切り替える。同じタブ内の再読み込み・画面移動では選択を保持する。幅650px以下では従来の上部「メニュー」による開閉を使う。

コンパクト表示でも項目名を常時表示する。アイコンは補助として扱い、ホバー時のツールチップだけに意味を依存させない。日本語・中国語・英語で項目名、操作名、ツールチップ、読み上げ名を切り替える。項目名は必要に応じて折り返す。選択中の項目とその親分類には背景・アクセント色・左端の線を付ける。

| 分類 | 専用アイコン | 目的 |
|---|---|---|
| 業務・作業 | ブリーフケース | タスク、資料、業務の進行 |
| スタジオ | ペンときらめき | サイト、画像、音声、動画の制作 |
| 管理・設定 | 歯車 | モデル、利用者、接続、権限の管理 |
| 高度な機能 | コード括弧 | 工程、スキル、学習、モデル管理 |
| 検証・診断 | 波形付き虫眼鏡 | 稼働、評価、検証、実行履歴 |

全42項目・分類に内容別の異なる線画を割り当てる。ホームは家、AI会話は吹き出し、書斎は本、個別チャットは重なる吹き出し、会議はビデオカメラ、アカウントは人物、起業はロケットとする。配下のメールは封筒、資料はフォルダー、権限は盾、履歴は時計など、各機能の対象を表す。定義は `src/navigation-icons.ts` に集約し、翻訳されない安定したIDで割り当てる。未定義の項目を同じ汎用アイコンで埋めない。

コンパクト表示の分類をクリック、Enter、Spaceで操作すると、通常幅へ展開してその分類を開く。既存のURL、画面内切替、権限別表示とAPI認可を維持する。アイコン自体は装飾としてCSS疑似要素に描画し、読み上げ名には項目名だけを使う。

検証結果と実機確認の範囲は [公開機能と制限](feature_scope.md) に記録する。
